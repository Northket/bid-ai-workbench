# 深圳建设工程投标 AI 工作台（第一阶段）

面向深圳建设工程招标场景的本地化 Web 平台：招标信息检索、招标文件解析、投标要求管理、历史项目数据查询与 AI 辅助投标。本仓库为**第一阶段完整可运行版本**，运行于 Windows 本地电脑，全中文界面。

---

## 一、技术架构

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite 5 | Ant Design 5 组件体系 + ECharts 图表 + React Router |
| 后端 | Python 3.12 + FastAPI | REST API，自动文档 `/docs` |
| 数据库 | SQLite（WAL 模式） | 零配置本地库，位于 `backend/data/platform.db` |
| 文件存储 | 本地文件系统 | `backend/uploads/`（招标文件 / 成果文件分目录） |

```
├─ 启动平台.bat          # 一键启动（生产模式，单端口 8000）
├─ 开发模式启动.bat       # 开发模式（前后端分离 + 热更新）
├─ backend/              # FastAPI 后端
│  ├─ main.py            # 入口（含 SPA 静态托管）
│  ├─ database.py        # SQLite 连接（WAL）
│  ├─ models.py          # 12 张数据表（SQLAlchemy 2.0）
│  ├─ schemas.py         # Pydantic 请求/响应模型
│  ├─ seed.py            # 演示数据种子（首次启动自动写入）
│  ├─ smoke_test.py      # 54 项接口自动化冒烟测试
│  ├─ routers/           # 8 个模块路由
│  ├─ data/platform.db   # 数据库文件（自动生成）
│  └─ uploads/           # 上传文件存储
└─ frontend/             # React 前端
   └─ src/pages/         # 11 个页面（工作台/项目库/公告/解析/要求/历史/AI/投标/设置）
```

## 二、启动方式

### 正式版本 vs 开发版本

| | 正式版本（`启动平台.bat`） | 开发版本（`开发模式启动.bat`） |
|---|---|---|
| 前端来源 | `frontend/dist` 构建产物 | Vite 开发服务器（5173） |
| 访问地址 | http://localhost:8000（单端口，页面+API 同源） | http://localhost:5173（/api 代理到 8000） |
| 代码修改 | 需重新 `npm run build` 生效 | 热更新，保存即生效 |
| 适用场景 | 日常使用、演示、部署 | 二次开发、调试 |

### 前置要求
- Windows 10/11，已安装 Python 3.10+（`python --version` 可用）
- 已安装 Node.js 18+（`node --version` 可用）

### 方式一：一键启动（推荐日常使用）
双击 **`启动平台.bat`**。首次运行会自动创建虚拟环境、安装依赖并构建前端；之后直接启动。启动后浏览器访问：

> **http://localhost:8000**

前端页面与 API 由同一端口提供（`frontend/dist` 构建产物由 FastAPI 托管）。关闭命令行窗口即停止服务。

### 方式二：开发模式（修改代码时使用）
双击 **`开发模式启动.bat`**：
- 前端（开发入口，热更新）：http://localhost:5173
- 后端 API（热重载）：http://localhost:8000 ，交互式文档：http://localhost:8000/docs

> Vite 已配置代理，前端开发服务器上的 `/api` 请求自动转发到 8000 端口。

### 手动启动（等价命令）
```bash
# 后端
cd backend
python -m venv venv
venv\Scripts\pip install -r requirements.txt
venv\Scripts\python -m uvicorn main:app --port 8000

# 前端（另一个终端）
cd frontend
npm install
npm run dev
```

1. **公告数据**：公告中心内容为演示数据（页面有醒目橙色「演示数据」标识），真实公示请访问[深圳公共资源交易平台](https://www.szggzy.cn)。点击「同步外部数据源」会如实返回"未配置"，不用假数据冒充。
2. **文档解析**：上传与存储为真实功能；「开始解析」产出的是结构化**演示解析结果**（结果页有标注）。真实解析引擎接口已预留。
3. **AI 回复**：所有 AI 回复均带「模拟回复」徽标，由规则引擎基于本地数据库统计生成（如中标均价、下浮率均为库内真实计算），未接入真实大模型 API。
4. **模型/向量/抓取配置**：系统设置中的对应入口为预留项，保存后不触发真实外部调用。

## 六、数据备份、恢复与迁移

- **备份**：双击 `备份数据库.bat`（或 `cd backend && venv\Scripts\python.exe scripts\backup_db.py`），生成 `backend/backups/backup_时间戳/`，含 SQLite 在线快照与上传文件副本，`MANIFEST.txt` 内有恢复步骤。
- **恢复**：停止服务 → 将备份目录中 `platform.db` 复制回 `backend/data/platform.db`（如含 uploads/ 一并复制回 `backend/uploads/`）→ 重启服务。
- **数据库迁移（Alembic）**：
  - 应用启动时自动将库结构升级到最新版本（升级前自动备份）；
  - 手动操作：`cd backend && venv\Scripts\python.exe scripts\db_migrate.py status|upgrade|downgrade`；
  - 结构变更历史见 `backend/alembic/versions/`（0001 基线 → 0002 软删除 → 0003 要求-文件关联）；
  - 回滚兜底：`downgrade` 失败时用对应备份文件整库还原。

## 七、整改后的数据与安全机制（2026-10-31）

1. **项目删除 = 软删除**：默认移入回收站（关联数据与文件全部保留、可恢复）；物理删除需显式 `permanent=true`，且文件仅解除关联/归档到 `uploads/_orphaned/`，永不销毁。
2. **历史统计统一服务**：列表与统计（含 AI 问答）共用 `services/history_service.py`，口径严格跟随筛选；下浮率仅统计"控制价>0 且 0<中标价≤控制价"的有效样本，中标价高于控制价的记录标记**待核验**并排除，结果展示有效样本数。
3. **上传安全**：分块写入、大小限制读取系统设置（默认 100MB）、扩展名+魔数双重校验（拒绝伪装文件）、文件名净化防路径穿越、失败自动清理；仅存储不执行任何宏/脚本。
4. **要求可溯源**：投标要求可关联原始招标文件（文件/页码/章节/条款/原文片段/提取方式），核验状态（待核验/已确认/已驳回）自动记录核验人与时间。
5. **密钥安全**：设置接口不回传 API Key 明文（仅"已配置"标记）；支持环境变量 `BID_MODEL_API_KEY` 优先；响应与日志均不含密钥。
6. **测试隔离**：`backend/tests/run_tests.py` 使用独立临时库与临时目录（123 项断言，含迁移演练），绝不触碰正式数据。

## 八、第二阶段：招标文件真实解析（2026-11-01）

- **解析引擎**（`backend/services/doc_parser/`）：PDF（PyMuPDF：逐页文本/章节层级/印刷页码/扫描页检测/定向表格提取）、DOCX（python-docx）、XLSX（openpyxl）；DOC/XLS 与 OCR 未实现时如实报错/标注，绝不伪造。
- **zip 交易包导入**：文件中心「导入招标文件交易包(.zip)」支持深圳交易平台封装（自动读取 Project.xml 元数据、记录原件 SHA-256、按扩展名白名单提取业务文件）。
- **解析工作台**：文件列表点「解析工作台」进入左右分栏——左侧原始 PDF 阅读（页码跳转），右侧七大类结构化结果（基本信息/时间节点/资格/否决条款/评标办法/技术标/商务资信）；点击条目左侧自动跳转对应页；每条保留原文依据+页码+章节；核验四态（待核验/已核验/存在疑问/提取失败）；人工修改保留原始提取；重新解析自动结转已核验条目；支持导出 Excel、一键登记为投标要求。
- 详见《第二阶段报告.md》。真实样本：某车辆段上盖物业项目（336 页，269+141 条结构化结果，原文回验 99%+）。
